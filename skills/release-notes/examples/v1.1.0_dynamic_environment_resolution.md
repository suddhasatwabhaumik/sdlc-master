# Release Notes: Dynamic Environment Resolution (`v1.1.0`)

## Module: `acme_mlops.core.env`

---

## 1. Overview

The **Dynamic Environment Resolution** module (`acme_mlops.core.env`) automates execution target detection across local developer workstations, on-premises Kubernetes/Airflow clusters, and Google Cloud Platform (Vertex AI, Cloud Run, GKE, Compute Engine).

Prior to this module, developers and ML pipelines had to manually set hardcoded environment identifiers or deal with failed cloud client instantiations when working offline. With dynamic resolution, the SDK intelligently senses its runtime environment using a deterministic 6-tier precedence hierarchy. Downstream subsystems—such as **SecretsResolver** and **DataConnector**—adapt transparently without requiring source code modifications.

---

## 2. Precedence Hierarchy Architecture

Environment resolution evaluates runtime signals in strict order from highest priority (Tier 1) to safe offline fallback (Tier 6):

```
┌────────────────────────────────────────────────────────────────────────┐
│                        Evaluation Precedence                           │
├─────────┬──────────────────────────────────┬───────────────────────────┤
│ Tier 1  │ In-Code Overrides                │ set_override_env(),       │
│         │                                  │ resolve_environment(...)  │
├─────────┼──────────────────────────────────┼───────────────────────────┤
│ Tier 2  │ Project YAML Configuration       │ mlops_config.yaml,        │
│         │                                  │ MLOPS_CONFIG_PATH         │
├─────────┼──────────────────────────────────┼───────────────────────────┤
│ Tier 3  │ GCP Metadata Socket & Runtime    │ metadata.google.internal  │
│         │ Context                          │ AIP_*, CLOUD_RUN_*, KFP_* │
├─────────┼──────────────────────────────────┼───────────────────────────┤
│ Tier 4  │ Kubernetes & Airflow Contexts    │ AIRFLOW_*, ServiceAccount │
│         │                                  │ token, KUBERNETES_SERVICE │
├─────────┼──────────────────────────────────┼───────────────────────────┤
│ Tier 5  │ Explicit Environment Variables   │ MLOPS_ENV, APP_ENV,      │
│         │                                  │ MLOPS_SANDBOX             │
├─────────┼──────────────────────────────────┼───────────────────────────┤
│ Tier 6  │ Default Sandbox Fallback         │ MLOPS_DEFAULT_ENV,        │
│         │                                  │ 'local'                   │
└─────────┴──────────────────────────────────┴───────────────────────────┘
```

### Tier Breakdown
1. **Tier 1 (In-Code Overrides)**:
   - `resolve_environment(override="...")`: Immediate invocation-level override.
   - `set_override_env("onprem")`: Global runtime override for interactive notebooks or test harnesses.
   - `clear_override_env()`: Clears in-code overrides and restores dynamic resolution.
2. **Tier 2 (Project YAML Config)**:
   - Resolves from `MLOPS_CONFIG_PATH` or `./mlops_config.yaml`.
   - Inspects keys: `default_environment`, `environment`, `execution_target`, or nested `env.target`.
3. **Tier 3 (GCP Metadata Socket Probe & Runtime Context)**:
   - Non-blocking TCP socket check to `metadata.google.internal:80` with a 200ms timeout (`check_gcp_metadata()`). Ensures zero lag on offline developer machines.
   - Container execution markers: `AIP_PIPELINE_RUN_ID`, `AIP_TENSORBOARD_LOG_DIR` (Vertex AI), `CLOUD_RUN_JOB`, `K_SERVICE` (Cloud Run), and `KFP_RUN_ID` (Kubeflow on GCP). Resolves to `"gcp"`.
4. **Tier 4 (Kubernetes & Airflow Contexts)**:
   - Checks `AIRFLOW_HOME`, `AIRFLOW_CTX_DAG_ID`, `AIRFLOW_CONFIG`.
   - Checks `/var/run/secrets/kubernetes.io/serviceaccount/token` mount or `KUBERNETES_SERVICE_HOST`.
   - On-prem K8s resolves to `"onprem"`; GKE clusters resolve to `"gcp"` because the Tier 3 socket probe succeeds first.
5. **Tier 5 (Environment Variables)**:
   - Evaluates `MLOPS_ENV`, `APP_ENV`, `EXECUTION_ENVIRONMENT`, `ENVIRONMENT`.
   - Evaluates sandbox flags: `MLOPS_SANDBOX=true`, `LOCAL_SANDBOX=1`, `SANDBOX_MODE=yes` safely forcing `"local"` mode.
6. **Tier 6 (Default Fallback)**:
   - Evaluates `MLOPS_DEFAULT_ENV` or defaults to `'local'` (safe offline developer sandbox).

## 3. How to Use in Your ML Workflow

### A. Basic Environment Resolution
```python
from acme_mlops.core.env import (
    resolve_environment,
    set_override_env,
    clear_override_env,
    get_gcp_project,
    ENV_GCP,
    ENV_LOCAL,
    ENV_ONPREM,
)

# 1. Resolve current runtime target dynamically
current_env = resolve_environment()
print(f"Active Environment: {current_env}")  # 'local', 'gcp', or 'onprem'

# 2. Query target GCP project (if in GCP or specified in config)
project_id = get_gcp_project()
print(f"Target Project: {project_id}")

# 3. Temporarily force local sandbox mode for unit testing
set_override_env("local")
assert resolve_environment() == "local"

# 4. Clear override to restore dynamic detection
clear_override_env()
```

### B. Downstream Routing: Unified Secrets Resolution
`SecretsResolver` (`src/acme_mlops/core/security.py`) automatically routes queries based on the resolved environment:
- In **`gcp`**: Queries Google Cloud Secret Manager (`projects/{project_id}/secrets/...`).
- In **`onprem`**: Queries HashiCorp Vault, then Kubernetes mounted secret files, then OS environment variables.
- In **`local`**: Falls back safely to local OS environment variables without throwing authentication errors.

```python
import os
from acme_mlops.core.security import SecretsResolver

# In local developer sandbox:
os.environ["DATABASE_PASSWORD"] = "local_sandbox_secret"

resolver = SecretsResolver()
db_pass = resolver.get_secret("database_password")
# Automatically retrieved from environment without needing Vault or Cloud credentials!
```

### C. Downstream Routing: Transparent Data Path Parity
`DataConnector` (`src/acme_mlops/io/connector.py`) seamlessly maps GCS bucket paths (`gs://...`) to local directory fixtures when running in local sandbox mode:

```python
from acme_mlops.io.connector import DataConnector

# Initialize connector with local POSIX mapping
connector = DataConnector(
    gcs_prefix="gs://example-cloud-project-forecast-data/template/",
    onprem_prefix="./template/"
)

# In GCP: reads live object from Cloud Storage
# In Local: transparently reads ./template/sample_input_template.csv
file_bytes = connector.read_file("gs://example-cloud-project-forecast-data/template/sample_input_template.csv")
```

### D. Interoperability with Application Config Engines
Client applications (e.g. `sample_forecasting_app`) can hook into `resolve_environment()` in their configuration loader (`src.core.config`):

```python
# src/core/config.py
from acme_mlops.core.env import resolve_environment

app_env = os.environ.get("APP_ENV") or resolve_environment()
# Dynamically loads configs/environments/local.yaml vs configs/environments/gcp.yaml
# with zero code changes required in pipeline forecasting scripts!
```
